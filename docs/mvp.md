# MVP: переиспользуемая основа v0.1

## Цель

Создать основу, которую можно подключить к новому небольшому tabular-соревнованию без форка ядра. Первое соревнование проверяет полный путь до submission artifact; второе — переносимость инструментов и шаблона.

Выпуск включает общую основу и документированные результаты двух reference-проектов. Сами прикладные решения живут в отдельных репозиториях.

## Состав

- Устанавливаемый Python-пакет, CLI и генератор competition-проекта.
- Версионируемые task, proposal, experiment spec/result и checkpoint contracts.
- Metadata-first загрузка, persistent cache, manifest и checksums.
- Tabular reference adapter и hooks для собственного ML pipeline.
- Run registry, usage/timing, timeout, budget cap и ограниченные retries.
- Восстановление состояния после прерывания без полного transcript.
- OpenCode-интеграция: оркестратор, research-роль с независимыми task instances, coding worker и read-only reviewer.
- Очередь гипотез, дедупликация, smoke-test и продвижение к full validation.
- Ограниченный параллельный research; последовательное обучение по умолчанию.
- Проверка submission и ручная отправка человеком.

Поддержка NLP/CV, распределенного scheduler, vector database, автоматического выбора competition и покупки compute следует после проверки первого выпуска.

## Definition of Done

- Зафиксированы пять исходных audit-runs на первом reference competition.
- Baseline первого проекта воспроизводится в заранее установленном допуске.
- Второй проект создается из шаблона; его schema, target, metric и split задаются локально, ядро не меняется.
- По README созданного проекта новый разработчик может пройти путь от установки до проверенного artifact.
- Повторный run не скачивает неизменные данные и учитывает cache hits.
- Run содержит hypothesis, budget, code/data versions, split, seed, environment, result и decision.
- При restart отсутствуют дублирование завершенного run и потеря учтенных затрат.
- Concurrency не нарушает resource/budget caps; конфликтующие изменения изолированы.
- Метрики разных протоколов валидации не смешиваются в ranking.
- Есть отчет сравнения последовательного и параллельного режима при одинаковом бюджете; режим по умолчанию выбирается по результатам.
- Правила проекта соревнования и версии зависимостей явно зафиксированы.
- Submission валидируется и отправляется только человеком.
